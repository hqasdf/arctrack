## Administrator-controlled ambiguous-deletion recovery

There is intentionally no public recovery endpoint, user-editable fence reset,
ordinary-user receipt setter or SQL bypass. Administrator recovery is an operator
procedure requiring an authenticated administrator and explicit case authorization.

1. Verify the requester's identity through existing support procedures. The user
   must still repeat normal signed-in password + DELETE confirmation to finish
   self-service deletion. An admin must not take submitted IDs as deletion authority.
2. Open a restricted case: verified Arc Track user ID, UTC event times, operation,
   version, lease expiry, safe error code and whether a durable receipt exists.
   Query selected metadata only; never SELECT * into shared logs. Do not copy
   ciphertext, state, verifier, tokens or API secrets into tickets/AI tools.
3. Stop new Garmin work for the affected account through the existing fence. For
   an unfenced interrupted case, any additional maintenance gate needs separately
   reviewed operator action. Wait for actual workers to stop; lease expiry alone
   does not prove a remote request had no effect. Preserve credentials and evidence.
4. If a terminal fenced receipt exists with credentials cleared, let the user retry
   the normal deletion form; no new Garmin authorization or repeated rotation.
5. If a known retryable provider outage exists and stored credentials remain usable,
   restore availability/configuration and use the normal guarded deletion retry.
   Never clear the fence merely to allow a reconnect while deletion is pending.
6. For lost rotation/exchange responses, mismatched identity, 401/404/invalid_grant,
   or remote success without a durable receipt, seek authoritative Garmin support
   confirmation tied to this application and provider user. A generic error or a
   user's screenshot alone does not prove remote deregistration.
7. If administrator-mediated provider cleanup or a manual receipt reconciliation
   becomes necessary, prepare a separate case-specific, reviewed operation. It must
   verify provider identity and explicit confirmation, require no active worker,
   use expected-version compare-and-set and preserve the fence. Only confirmed
   deregistration may permit token removal/receipt reconciliation. There is no
   implementation or executable bypass for this in the current release.
8. If proof/recovery is unavailable, keep the account and credentials protected,
   explain the unresolved state, and escalate. Do not report complete deletion,
   drop tables, disable triggers, reset the fence or delete Auth to force success.

Garmin requests, PostgreSQL writes and Auth deletion cannot be one atomic transaction.
Automatic recovery is not guaranteed across process death or lost remote responses.
Before broader rollout, agree on a provider-supported recovery process and support
ownership; otherwise keep testing limited to the approved test window.

## Rollback and privacy gates

After real connections exist, prefer forward correction. Preserve Garmin tables,
fences, encrypted credentials, receipts and keys. Do not restore old deletion code
that cascades credentials away without remote cleanup. If a code rollback is needed,
retain the deletion-aware path or temporarily pause deletion and new connections
with an approved maintenance release. Merely removing Garmin config is insufficient:
existing connected accounts would still require cleanup.

Restoring a backup does not restore revoked Garmin authorizations and can reintroduce
older rotating tokens or deleted accounts. Never restore the entire live database
just to undo these additive migrations. Rehearse on an isolated restore and obtain
separate approval for any production recovery.

The privacy page now describes optional connection metadata, encrypted credentials,
temporary OAuth records, no measurement import, deletion retries and coach isolation.
Existing backup/log retention placeholders remain unconfirmed and are a publication
blocker. No Garmin-to-AI path was found in the integration; tests use synthetic
responses. This code review cannot certify vendors' independent internal practices.
